# Верста — фронтенд Car Rental

Веб-интерфейс для посуточной аренды автомобилей. Исходники интерфейса находятся в `frontend/`.

## Локальный запуск

Требуется Node.js 20.19+ в ветке 20 или Node.js 22.12 и новее.


1. Запусти PostgreSQL и Spring Boot как обычно. По умолчанию прокси фронтенда обращается к `http://localhost:8080`.
2. В папке `frontend` выполни:

   ```bash
   npm ci
   npm run dev
   ```

3. Открой `http://127.0.0.1:3000`. Если сервер аренды выключен или автопарк пуст, открой `http://127.0.0.1:3000/?demo=1`. Демо работает на локальных примерах, бронь и отмена сохраняются до перезагрузки страницы.

Если Spring Boot работает по другому адресу, укажи его при запуске, например `CAR_RENTAL_API_URL=http://localhost:8081 npm run dev`.

## API

| Действие | Маршрут Spring Boot |
| --- | --- |
| Автопарк и характеристики автомобиля | `GET /cars`, `GET /cars/{id}` |
| Полный автопарк в интерфейсе администратора | `GET /cars/all` |
| Классы автомобилей | `GET /categories`. Детали класса доступны по `GET /categories/{id}` |
| Регистрация и вход | `POST /auth/register`, `POST /auth/login` |
| Обновление сессии | `POST /auth/refresh` с JSON `{"refreshToken":"…"}` |
| Свой профиль | `GET /users/me`, `DELETE /users/me` |
| Свои аренды | `GET /rentals/my`, `GET /rentals/my/{id}`, `POST /rentals`, `POST /rentals/me/cancel/{id}` |
| Свои платежи | `POST /payments/rentals/{id}`, поиск своего платежа для роли `USER` по `GET /payments/{id}` |
| Пользователь в панели менеджера и администратора | `GET /users?userId={id}`, `DELETE /users?userId={id}` |
| Аренды в панели менеджера и администратора | `GET /rentals?userId={id}`, `GET /rentals/{id}`, `POST /rentals/{id}/cancel` |

Пункт «Панель» появляется для ролей `MANAGER` и `ADMIN`. У администратора доступны панель, полный автопарк и выход из аккаунта. Интерфейс выбирает разделы по claim `role` в access-токене. Сервер проверяет права на каждый запрос. Оплата создаёт запись в статусе `PENDING`, пользователь с ролью `USER` может найти её по ID.

Пара токенов хранится в `sessionStorage`. Фронтенд перед запросом с авторизацией проверяет срок access-токена и обновляет пару по необходимости. При `401` защищённый запрос можно повторить один раз после refresh. Несколько одновременных запросов ждут один refresh. Отказ в обновлении завершает сессию, а при временной ошибке повторить действие можно позже.

Поиск, сортировка и фильтр по классу работают по ответу каталога. «Рядом со мной» использует геолокацию браузера или координаты, введённые вручную. Координаты пользователя хранятся на странице. Фронтенд сортирует машины из каталога по расстоянию по прямой. Даты передаются в формате `LocalDateTime`, стоимость брони берётся из API. Поле `imageUrl` в ответе `GET /cars` может содержать прямую ссылку на фотографию. Если ссылки нет или фото не загрузилось, показывается локальная иллюстрация для известных моделей или пиктограмма.

## Яндекс Карты

Без ключа открывается карта OpenStreetMap. На ней отображаются машины из каталога, а нажатие на метку открывает карточку. Кнопка «Виджет Яндекса» переключает карту на встроенный виджет со стандартными метками.

Чтобы использовать метки-машинки с ценой на подложке Яндекс Карт, подключи JavaScript API 3.0:

1. Получи ключ в [кабинете разработчика Яндекс Карт](https://developer.tech.yandex.ru/) и задай ограничение по HTTP Referer. Для локальной разработки добавь адрес, на котором открываешь фронтенд, например `127.0.0.1`.
2. Создай `frontend/.env.local` и добавь `VITE_YANDEX_MAPS_API_KEY=твой_ключ`.
3. Перезапусти Vite. При статическом размещении собери фронтенд с этой переменной.

В виджете Яндекс может показывать рекламу. Для отключения добавь в `.env.local` переменную `VITE_YANDEX_MAPS_WIDGET_KEY` с ключом тарифа «Базовый (без рекламы)». Фронтенд передаст ключ виджету в параметре `jsApiKey`. [Документация о рекламе](https://yandex.ru/maps-api/docs/constructor/concept/ads.html)

[Документация JavaScript API 3.0](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html)

## Сборка

`npm run build` создаёт `dist/`. Команда `npm run preview` позволяет проверить сборку с тем же прокси. Чтобы раздавать `dist/` на другом сервере, настрой проксирование `/api` к Spring Boot со снятием префикса `/api` или задай `VITE_API_BASE_URL` перед сборкой и настрой CORS на стороне API.
